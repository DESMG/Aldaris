# 后续 Q：项目说明、隐私政策与使用条款文案

状态：等待确认。本轮不修改这些文案。

三者没有直接互相否定的表述，但同一事实多次出现，部分摘要与正文只差少量措辞。后续修改时应先确定每项事实的主版本，再决定页面提示保留摘要、政策保留处理细节、条款保留使用责任。

## 三者之间

- [ ] Q3：团队可见范围是否需要在创建工单和发表评论的位置增加短提示？隐私政策和使用条款多次说明工单、评论、图片及时间线对同一部署内的已登录成员可见，项目内提交界面没有对应提示。
- [ ] Q4：提及和指派“不发送通知”是否需要进入项目内说明？隐私政策和使用条款都说明提及、指派不会产生站内或外部通知，但提及输入框和负责人选择框只说明搜索与人数限制。
- [ ] Q5：账户删除后的保留范围是否统一表述为“无法登录，但工单、评论、时间线和操作记录可能继续保留账户信息”？删除账户对话框只写工单和评论保留；隐私政策与使用条款还提到历史记录、操作记录、个人信息和他人副本。
- [ ] Q6：“不承诺永久保存、备份或恢复”是否只在政策和条款中承担完整说明，项目内只保留与当前操作直接有关的图片留存提示？当前多个位置都要求另行保存重要内容，但对象分别是图片、草稿和全部协作数据。
- [ ] Q7：密码泄露检查的用词是否统一为“泄露记录匹配”或“泄露风险”？项目内确认框写“此密码已发生泄露事件”，隐私政策写“泄露风险检查”，使用条款写“泄露查询只是辅助措施”。应确定哪个表述准确描述检查结果。
- [ ] Q8：账户字段究竟要求“昵称”还是“中文真实姓名”？项目内字段标签是“昵称”，帮助文字要求中文真实姓名；隐私政策写“姓名或昵称”；使用条款要求“准确且可供团队识别的资料”。应先确定业务规则，再统一字段名称和政策描述。

## 项目内说明内部

- [ ] Q9：“文字草稿自动保存；刷新后可恢复，图片不会保存。”在新建工单和发表回复中逐字相同，但一处使用信息提示，一处使用次要说明。是否统一组件和提示级别？
- [ ] Q10：编辑评论、创建用户、编辑用户及重新登录对话框都在说明“哪些内容可以恢复、哪些需要重新填写”，句式和信息顺序不同。是否统一为“已保存内容 → 未保存内容 → 离开后的结果”的顺序？
- [ ] Q11：状态文案是否统一区分“已关闭”这个状态总称与“不计划处理”这个关闭原因？列表状态标签显示“已关闭”，关闭原因菜单和操作提示使用“不计划处理”，需要确定在详情、时间线和操作记录中的展示规则。
- [ ] Q12：“用户”“普通用户”“成员”是否分别代表账户角色、登录人员和协作参与者？当前角色选择、负责人搜索、政策及条款使用了三种称呼，后续应确定术语边界。

## 隐私政策内部

- [ ] Q13：开头警告、信息使用目的和可见范围章节都说明团队成员可查看内容。是否保留开头警告作摘要，并把正文集中到“可见范围与信息共享”，其他章节只引用该结论？
- [ ] Q14：开头警告与保存期限章节都写图片保留 30 天和容量不足时提前清理。摘要是否只保留期限与提前清理，恢复、通知和原位置显示方式只留在正文？
- [ ] Q15：开头警告与查阅、更正、删除章节都写删除账户不会删除历史内容。摘要是否只保留结论，正文再列出姓名、用户名、工单、评论和历史记录？
